# Following one request through the experiment

Consider a 129-token prompt routed from p1 through l11 to d1 with an eight-token output budget. These steps follow the native GPU backend. The simulator substitutes queue and service models for the workers while retaining the diagnosis and evaluation interface.

1. **Start the workers.** The coordinator starts independent, single-GPU vLLM servers with identical pinned Qwen weights and tokenizer. A private HTTP address, cache directory and server log identify each worker. The pilot waits for the expected model and version.
2. **Prove the handoff.** Run the same prompt unsplit and split. Prefill must return the first token, decode must import 128 cached prompt tokens for this example, and the combined eight greedy IDs must equal the unsplit sequence. Every route must pass before fitting begins. See `failslow/native_server.py` and `failslow/connector.py`.
3. **Offer traffic.** A seeded arrival schedule chooses a route, prompt length and output budget. The coordinator constructs tokenized natural-language questions with unique request prefixes. It records offered arrival time even when a worker is busy. Requests serialize on each worker. Different workers can operate concurrently.
4. **Measure prefill.** The prefill endpoint receives a streaming completion request for one token. The connector brackets its forward with synchronization and logs a request identifier. The client joins the token to that forward. Time from scheduled arrival to receipt is TTFT and includes waiting.
5. **Move KV and decode.** The coordinator measures the file copy between worker directories. The decode endpoint receives the original prompt and first token, loads the block-aligned prefix and produces seven more tokens. The observer records each forward and each client-side inter-token gap. The first gap includes the handoff. GPU export and import contribute to the associated worker spans. The copy span measures a logical single-host path.
6. **Learn healthy service.** Whole runs populate independent fit, scale and threshold splits. Regress median and p95 log duration on stage work. A long prompt or a larger cache transfer can therefore have a higher expected duration. Normalize positive excess above p95 by the fitted spread. Average within requests before averaging across them so long generations do not dominate.
7. **Diagnose causally.** At each tick, consume completed observations available by that tick. Check configuration, workload support and sample counts. Standard runs use a 30-second window, ten-second ticks and two consecutive threshold crossings. Rank supported workers and paths. Combine evidence of changed demand, service degradation and client SLO breaches into an explanation. Insufficient evidence can yield unknown.
8. **Test on held-out conditions.** The harness applies a timed delay on a selected worker forward or path copy. Matched controls reuse the offered workload and routes. The observer receives only telemetry. After prediction the evaluator joins the separate fault schedule to count first-ranked hits, misses, false episodes, eligible explanation windows, and detection delays. A hit several ticks later and a correct first ranking answer different questions.
9. **Inspect the evidence.** In the run directory open study.json for assignments, pilot.json for equivalence, calibration.json for thresholds, incidents.csv for first rankings and healthy_runs.csv for false episodes. Use the per-request tables, generation pairs and component scores to explain a particular incident. An incomplete request at the horizon is right-censored. The report provides observed results for each execution environment.
